For review

1. Where it opens from

A Log button on the brain's row in Your boards, opening this full screen. It is a bench and support tool, so it stays off the Shop and Build screens.

2. Brain only, for now

The brain serves the app, so it can serve its own log. A node's log would need the brain to fetch it over NodeLink. That is possible later, and the Boards chip already covers most of what a node says, from the brain's side.

3. What it can and can't show

Everything the board prints, including library errors like Connection reset by peer, from about 32 KB kept in spare PSRAM. Not the first second of boot, and nothing from before the last restart. A restart is marked in the log. For history across restarts, the link log already exists.

4. Updates by polling, once a second

The app asks for new lines every second and gets only what it hasn't seen. If the phone falls behind and the brain's buffer wraps, the gap is marked rather than hidden. Polling costs nothing while the screen is closed.

5. Password-protected

The same login as the rest of the API. Nothing printed today includes a WiFi or device password; that gets checked before this ships.

6. The same lines, without the app

GET /api/serial?from=N is what this screen polls, and it is a plain endpoint, so bash dev.sh log can follow it from a laptop with no USB cable. That is how Claude reads the brain while you run a test at the bench.
