Marking a problem on the canvas

The guide bar can say “Table Saw · Overarm Collector, Wye are drawn over another run.” That is a true sentence and a useless one: it is one line at the top of a canvas you are scrolled around inside, naming two pieces without saying where. This page is about the graphical half — and about the case that makes it hard, which is a run that is invisible because something is drawn on top of it.

Throwaway. Whatever wins folds into canvas.html and this page moves to archived/.

1 · What the colours already mean

A new marking has to survive a palette that is nearly full. Everything here is load-bearing today:

  • Accent orange — unfinished. An open stub, a gate nobody has set up yet. Not available: a problem is not the same as unfinished work, and the whole point of the orange dot is that it is a to-do you can clear.
  • Red / danger — used by the app for destructive and live-fault states (--danger, the “Cap them” button). Tempting, and probably too strong: an overlap is a picture that cannot be drawn, not a shop that will hurt you.
  • Green — set up, ready.
  • Azure — a cable. Violet — the collector barrel. Grey — duct.

The candidate is magenta (--problem: #c264e0) — unspoken-for, reads clearly against both the grey ducts and the azure cables, and does not say “danger”. Shown throughout below. It is a proposal, not a decision.

“Show me” is the part that is not a colour. Hover cannot be the only way in, and neither can noticing a small mark on a canvas three screens wide — so the bar carries a control that pans to the fault and focuses it. Press it above to see the focused state (halo + dim + peel together).

3 · The three for a piece

A · Halo

A ring around the glyph, with a soft outer glow so it reads at a glance when zoomed out. Always visible, no gesture needed.

Against: a shop with four problems has four halos and starts to look decorated. Competes with the drop-target ring, which is also a ring around a glyph.

B · Corner flag

A badge on the corner, exactly where the orange “needs setup” dot and the green tick already live — so it joins a row that already exists rather than inventing a second language.

Against: that corner is getting crowded, and a 9px badge is easy to miss on a phone. Says which piece, not what.

C · Halo + dim the rest

Focus: the implicated pieces keep full contrast, everything else drops to 22%. Dims rather than hides, per the standing rule. This is the “Show me” state rather than a resting state.

Against: only works for one problem at a time, so it needs the bar to cycle. Which may be right — problems get fixed one at a time.

These are not exclusive, and the likely answer is B at rest and C on “Show me”. A badge that is always there so nothing is silently wrong, and a focus mode for actually finding it. A is the one to drop if two is too many.

4 · The hard one: marking a run you cannot see

An overlap is not about a piece. It is about two runs, one of which is invisible by definition — it is underneath the other. A halo on a box cannot say that, and neither can naming the pieces the runs feed, which is what the guide bar does today.

Bracket the stretch

A magenta bracket under the doubled length, captioned. Says exactly where and exactly how much, and needs no gesture.

Against: it is one more line on a canvas whose problem is too many lines. And it names a length, not the two runs involved.

Peel apart

On focus, the run underneath slides clear by ~11px and labels itself, then settles back. You see the hidden run and can follow it, which is the actual question: where does that one go?

Against: it is a lie for as long as it lasts — the run is drawn where it is not. Wants to be obviously temporary.

Both

Bracket at rest so the fault is never silent, peel on focus so it can be understood. Try the Both button above.

Note: if the offset work lands (see the branch TODO), a permanent small offset may replace the peel entirely — two runs drawn 6px apart are legible without any marking at all.

5 · What I need decided

1 · Colour. Magenta as shown, or fold problems into the existing --danger red? Magenta costs a new entry in the vocabulary; red costs the distinction between “this is broken” and “this will hurt you”.

2 · Resting vs focused. Is a problem always marked on the canvas, or only when you ask via the guide bar? Always-marked is honest and gets noisy; on-demand is clean and lets a fault sit unnoticed.

3 · Does the overlap get a bracket at all, or do we accept that overlaps are only findable through “Show me”, on the grounds that the offset work should make most of them stop happening?

4 · One problem at a time, or all of them? “Show me” implies a cursor through a list. That is a small piece of UI the canvas does not have yet.
