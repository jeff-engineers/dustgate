DustGate · build canvas

The second-duct gesture

Adding a pickup from the tool's menu drops an unattached open end onto the canvas and leaves you to plumb it. It picks the cell blind, and on the demo shop it picks a cell that is already an outlet on the main gate — so the new port looks wired to a gate that is busy feeding something else.

The proposal: stop creating the port before it has a run. Drag a run end onto a machine that already has a duct, confirm what it is, and the port is born already connected to the gate you chose.

What the menu route does today

The open end lands on a live outlet

measured
Three failures in one step

One: addPickup() writes the cell directly and never asks whether anything is there, so it can land on an outlet in use. Two: the junction it creates has no parent duct, so the document is invalid before you have done anything wrong. Three: you now have to find that end and plumb it, and the shop nags at you the whole time.

Drag a run onto the machine instead

the proposal
Never an invalid intermediate state

The port is created already attached to the gate you dragged from, so there is no orphan, no blind cell choice, and no window where the shop is broken. It reuses the run-end drag that already exists — nothing new to learn.

The confirmation

A drop on an occupied machine is ambiguous — it could be a slip. So it asks, and the question names the machine rather than the schema.

What it asks

Two choices, because there are only two: it is a second pickup, or it was a misdrop. Replacing the existing run is deliberately not offered — that is a delete wearing a friendly hat, and the run you would destroy is the one the machine cannot work without.

Why this needs no schema change

Same structure the model has carried since the shop container, and the same one addPickup() already builds — this only changes when the port is created and what it is attached to at that moment.

Open question · how the second run is drawn

You asked for dashed. That collides with something. Dashes already mean unfinished run on this canvas — an open end you have not plumbed yet wears them, and so does a duct mid-drag. And secondary-ports.html settled the opposite for Option A: "The run stays solid. It is real ductwork, not a relationship." A second pickup's duct carries real air, so a treatment that says "provisional" is saying the wrong thing about it.

Three ways out, below. If you still want true dashes, that is a fine call — it just means re-languaging "unfinished", which is a separate change worth doing on purpose rather than by side effect.

A · Solid, like any duct

standing decision
Truthful, but harder to trace

The hood glyph and its role caption already say which inlet is which. Nothing to unlearn — but on a busy canvas you cannot tell at a glance which of two runs is the supplemental one without following it to its end.

B · Solid, but lighter

suggested
Distinguishes without stealing the dash

A narrower, slightly quieter stroke gets you the at-a-glance read you want while leaving dashes to mean what they already mean. It also matches the physical truth: a hood line generally is the smaller pipe.

C · Truly dashed

as asked
Two meanings, one line style

Unmistakable on its own, ambiguous in context: a half-drawn run and a finished supplemental run become the same picture. Workable only if "unfinished" moves to a different treatment first.

Open question · does this reopen cross-system?

You cut cross-system pickups earlier today — tools only ever exist in one place, on their primary system — and I have already banded that section of secondary-ports.html and corrected the constraint in CLAUDE.md. The gesture does not require reopening it.

Same-system only (recommended). Dropping a run end from system B onto a machine in system A is refused, with the reason named — the same way a drop onto an occupied cell is. Everything stays inside one blower's tree, the seam stays a wall, and nothing about the decision you just made changes.

Cross-system. If you do want it back, it is worth being deliberate: it brings back the seam-crossing duct, the both-collectors-open control scheme, and the question of what happens when one collector is off and the other is running. Say the word and I will unband that section rather than quietly re-deriving it.

What it takes to build

PieceState
Drop target The run-end drag already hit-tests pieces. It needs to accept a machine that already has a primary port instead of refusing it.
The confirmation New — a small sheet, the same one the canvas already uses for gate and plug setup.
Creating the port addSupplementalPort() exists and is what addPickup() already calls. It would be handed the dragged run as the parent rather than a freshly-invented open end.
Placement Deleted, not fixed. A pickup has no cell — the hood rides its machine's box — so the blind cells.set() that lands on a live outlet stops existing.
The old menu item Removed. Two ways in would mean keeping the broken one.
Line treatment One flag on the duct, once B or C is settled above.

Nothing here touches the model, the firmware, or validateShop — the shape it produces is the one the schema has always described.
