Stacking the shop down the page

The auto-layout spreads sibling runs sideways, so a shop gets wider with every branch. The fit is width-bound, so on a phone that scales the whole drawing down and leaves the bottom half of the screen empty. Stacking the branches instead trades width for height — which is the dimension a phone has spare.

A sliding gate stays horizontal in all of these. Its outlets run along its bottom edge and each tool locks to the cell beneath its own outlet — that's the glyph, the outlet geometry and the router, not styling. So "vertical" means the branches stack; it never means turning a gate on its side. The only real question is how the trunk gets past a branch to reach the next one.

Trunk never touches a branch

The trunk gets a lane of its own and every branch feeds off it sideways. Costs one column against option A, and buys a drawing where the main line is unmistakable and nothing crosses anything. This is the one that reads like real ductwork.

The trunk steps right under the first branch and carries on down. Same width as B here, but it indents again at every nesting level — a deep shop walks off the right edge, which is the problem we're leaving.

What this does not change

Auto-layout only runs on a shop that has no saved arrangement. Anything you have already positioned by hand stays exactly where you put it, on every device — so this changes the starting point for new shops, not your bench setup.

And it isn't per-device: the layout is saved into the document, so a shop first opened on the phone keeps its stacked arrangement on the desktop. That seems right — a vertical drawing reads fine on a wide screen, where the sideways one was only ever readable because the screen was wide.
