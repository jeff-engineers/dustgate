DustGate · build canvas

A second collector on the same canvas

The model has carried N airflow systems for a while — the container, the per-system checks, the live view's "3 dust collectors". The build canvas is the last thing that only knows about one: it picks systems[0] at load and never offers another.

The load-bearing fact: a system is exactly one collector and one duct tree, and no duct is ever shared between two of them — that's structural in shop.js, not a convention. Air never crosses between systems. Only a machine does, when its overarm pickup hangs off a different collector than its cabinet port. So the boundary never has to be searched for; it only has to be drawn.

Each system on its own ground

A grey ground per system and exactly one empty cell row between them. No name chip, no gutter, no double space — the ground itself says where one system stops. A new collector lands on the top-left cell of its own area, which is where the trunk lane already starts.

Two systems

one row apart
No line, no label, no wasted row

The dashed amber run is the table saw's overarm pickup, which hangs off the shop vac while its cabinet port stays on the cyclone. It is not a duct — it's the machine, saying "these two boxes are one tool". It is the only thing that ever crosses the gap.

Why one row is enough

the band rule

Each system owns a contiguous range of rows. A drag that would land in the next system's rows pushes that system down instead of crossing into it, so the two grounds never interleave and the gap stays exactly one cell. That invariant is what makes the boundary free to draw — no search, no A* run per repaint, and no shop where the answer is "there isn't one".

Adding a system is a row in the ⋯ menu next to Import and Export, since a shop grows a second collector roughly once. The collector appears on the top-left cell of the new ground with an open end below it, and takes its name from whatever smart outlet you pair to it — so no dialog.

Telling a tool from a gate

Today they're both a dark rounded rectangle with a pale label, differing mainly in proportion — the first thing lost when the drawing scales to fit a phone. Three ways to spend the azure on it. All three leave gates, valves and the collector exactly as they are, so whatever changes, changes on the machines.

A · Azure ground

the pick
Distinct at 40%

A dark azure ground on machines only, with the plug chip picking up the same family. Saturation stays low: the cable's full azure keeps meaning "wire", and a tool never competes with one. The gate label drops to small muted caps so a gate reads as infrastructure.

B · Azure outline

Loudest, and ambiguous

The full #38b6f0 as an outline. It separates the two instantly, but azure is already the wiring layer's colour — a tool wearing it beside a live cable reads as wired or selected rather than as a machine. Shown because it's the version worth rejecting deliberately.

C · Azure on the plug only

Too small to carry it

Leaves the body alone and puts the azure where it's already earned — the plug. Honest, and it fails at exactly the zoom level the problem shows up at, which is the whole reason for asking.

What this doesn't touch

Nothing here changes the topology, the router, or what saves to the device. The system ground is a rectangle drawn under a band; the tool treatment is fill, stroke and label weight. Both are reversible in an afternoon.
