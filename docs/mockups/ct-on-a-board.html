A Clamp on a Board

Every sensing device DustGate has ever had sits AT the thing it watches, and is found by searching the network for it. A current clamp is neither: it is soldered to a board that may be across the shop, and no amount of searching will find it. This works out what that looks like to a woodworker.

The model and firmware are built; none of this is. sensor.ct validates, the primary pushes a CONFIG, a node decides the bit and reports it, and the routing brain acts on it — but nothing has run on hardware and the canvas has no way to create one. Today the only way to make a CT-sensed tool is to PUT a topology by hand.

Where the clamp rows come from

Not from a sweep — a clamp has no address to find. The board says so in its WELCOME, the same frame that already reports how many servos it can drive. That makes the row a fact about hardware rather than something a person typed, and a board that knows what it is soldered to cannot be wrong about it.

It is also the smallest possible piece of the "capabilities" idea: one more number in caps, not a refactor. A board with no clamp simply contributes no row, and a tray with no clamp rows is the correct empty state, not a missing feature.

What to call it

Not "outlets" — one of these is not an outlet. Candidates, none settled: Devices (accurate, bland), Plugs & clamps (says exactly what is in there, ages badly the moment a third kind arrives), What DustGate can see (woodworker-plain, long). Leaning Devices.

3 · On the canvas, it draws its own cable

A plug needs no line: it sits at the tool and the association is obvious. A clamp's lead physically runs from the tool to a board — so the line is not a diagram of a relationship, it is a drawing of a wire the woodworker will have to run across their floor. Drawn honestly, a long one is telling them to move the board.

Three lines already mean things here

Duct runs are solid. A secondary port's cross-system run is grey dashed and thinner. An unfinished run's stub is accent orange. CLAUDE.md records that the meaning of a dashed line was re-litigated three times, so a fourth dashed vocabulary is the one thing not to reach for by default. Dotted in a cool signal colour reads as "not air" at a glance, which is the distinction that matters most.

It routes like a cable, not like a duct

Same orthogonal routing the board cables already use, because it is a board cable — but it must be allowed to cross duct runs, which ducts may not do to each other. Air cannot cross; a wire on the floor obviously can. Unresolved: whether it should route around machine boxes or straight through them.

4 · Open, with a position

A clamp is dragged, like a plug — onto either

The gesture already exists and the mental model is identical: "this device watches that thing". It drops on a machine or the collector, exactly as a plug does.

The collector was the harder call and it went the same way. A clamp answers a sharper question there than on a tool: every way DustGate commands a blower is STATELESS — a servo on a fob, an RF frame — so sensor is the only thing that can say the press landed, and a 240 V blower has no plug to meter. Splitting it would have left the two setup sheets explaining an arbitrary difference.

The two sheets converge on one control

The collector sheet already asks Watched by as a radiogroup — metering plug / current clamp / nothing. The tools screen does not: it pairs a plug and asks for a threshold, a shape from before any of this existed. It gets the same radiogroup, so the answer to "how does DustGate know this is running" looks identical wherever you are standing.

Its greyed reason — "threshold shape undecided" — dies with the change. RFC §5.4b settled it: there is no threshold. The node compares against its own noise floor and sends one bit, so a clamp has nothing to ask the user for except which board it is on.

One clamp per board

The C5 has exactly one analog pad on the edge (D0), so a board contributes at most one row and the tray never shows two clamps on one board. That is a hardware fact, not a rule — worth stating so nobody designs a picker for a second channel.

What a clamped tool shows when its board is asleep

The planer node is powered from the planer, so it vanishes whenever the machine is switched off at the wall — normal, and marked intermittent in the layout. The tool reads as off, correctly. Unbuilt: nothing reads that flag yet, so the ordinary board-offline warning still fires every time. A clamped tool probably needs a third state on the canvas — watched / running / not reporting.
