## node-links-stay-up → main

42 commits. The thread: **a shop of eight nodes and a dozen plugs has to fit on one small board, and it has to be maintainable without a ladder and a USB cable.** Memory first, then work the brain no longer has to do, then updating over WiFi, then — because the bench showed a brain that dials every node is fragile — **nodes that dial their own brain.**

### What changed

**Nodes dial their own primary** (new since the first draft of this PR)
- A claimed node now dials the primary itself (`node/BrainLink.h`): the address from a `WHERE`, a UDP broadcast beacon the primary sends every 5 s while any node is down, the last address it linked on (NVS), `<owner>.local`, and finally a slow sweep of the /24. An unclaimed node never dials anyone — pairing is still the primary's move.
- The primary takes a `JOIN` on its existing `/nodelink` listener, binds it to the pairing's bus and answers with the usual `HELLO`; no task and no per-node address on that side. A node that dials in costs the primary no dial-out task while linked (a supervisor starts one only if the node has not appeared after a boot grace of 10 s, or has dropped and not come back).
- **Additive, protocol version stays 1**: new frames `JOIN`, `REFUSE`, `WHERE` and `caps.join`; an old end ignores what it does not know, so old nodes are still dialled. Paired JS/C++ tests, `CLAUDE.md` rows.
- One-link rule on the node: a second `HELLO` while the link it dialled is healthy is closed — it used to replace the owner, which is what made every command after it read "not the owner of this node".
- A socket counts as the link only after the primary answers `JOIN` with a `HELLO` (the sweep was "linking" to other nodes). A refused node backs off instead of redialling every 1.5 s. A fresh beacon wakes a node out of its backoff. A busy primary (< 24 KB free) answers `JOIN` with `REFUSE busy`.
- Nodes serve `GET /api/brainlink` (state and the last few things the link task did) so "why has it not found the primary?" is answerable without a serial cable.
- `docs/nodes-dial-the-brain-plan.md` has the design and the headroom math.

**Pairing a node no longer drops the others** (`control/NodeLinkPlan.h`); links start one at a time.

**Memory.** Layout validation and the status/node documents live in PSRAM; the node-link pool lives in PSRAM; the page-load guard no longer wedges (three expiring slots, WebSocket paths exempt).

**The board that controls a tool polls its plug.** CONFIG sensors gain kind `plug`, SENSE gains `watts`/`plug`, WELCOME gains `caps.plug`; the owner rule is `plugOwners` ↔ `plugOwnerOf` from one shared fixture.

**OTA — update over WiFi.** Both partition tables gain a second app slot (**each board needs one cable flash for this**). `bash dev.sh ota` builds the brain and both node programs from one commit, posts the brain image, waits for it to prove itself, stages the node images. New images run on probation (valid after 30 s healthy, rolled back by the bootloader or after 3 minutes). Nodes **pull** their image over HTTP; manual, one node at a time, refused while a tool runs or a gate moves.

**Settings → Danger zone:** "Reset layout" and "Reset everything".

**Every line the brain prints carries its own timestamp** (UTC once NTP answers, uptime before) on USB and in the API log; `brain-log.py` and the Brain log screen show it in local time. Nodes get host time from the monitor.

**Bug fixes found on the bench**
- `Ws.GetConfig` was called with a 0 ms timeout (a virtual's default argument binds to the static type), so no Shelly Gen4 plug could be taken over, renamed or paired.
- `end()` / pause / unpair left a node's own socket attached to the old pairing, so the restarted bus never re-sent the handshake while the node thought it was linked.
- The routing runtime returns early until a layout is loaded, so nothing pinged node-initiated links and every node read "offline" six seconds after joining; they are pumped from `loop()` now.

**Dev tooling:** `dev.sh ota/log/linklog` resolve the board's address once; `ota` retries a build once; `links pause|resume`; `heap`/`tasks`; `tools/ws-spike.js`; `brain-log.py --once` reads to the end of the buffer.

### Verified on hardware (brain + five nodes, 2026-10-04)

- OTA: brain update both slots; node update; brain rollback and node rollback; node power-cut during probation; a cut download fails cleanly.
- **Nodes dialling in:** first node-initiated link; all five dial in after a brain reboot; **8 brain reboots and 4 pause/resume cycles, every node back online each time (about 5–15 s), no flaps** (the first run of the pause cycles failed all four — that is how the stale-socket bug was found).
- Page-load guard under repeated cold loads; layout saves; update refused while a tool runs; both reset buttons; node plug polling handed to the node; the Gen4 takeover/rename path after the timeout fix.

### NOT verified — do not read as working

- **The brain's memory is still thin.** With five nodes it idles near 40 KB internal RAM free, and a board scan or a layout save in the same few seconds took the low-water mark to 1.5–7 KB without a crash. Nothing leaked. This is the reason for the follow-up below, not something this PR settles.
- **Node updates over the brain's own HTTP are unreliable under that pressure:** three of five failed twice with "download stalled" while the UI was in use.
- A node dialling in through the brain's per-node-task removal after a long outage; hard power cuts of a node; a brain and node on different access points on purpose; hours-long idle soak.
- Slider-node OTA (never installed on a real slider); node plug polling under a real load.
- Carried from the previous PR: collector press fixes against a real collector, the plug re-find by sweep, the gzip path under a real cold load.

### Known and open

- The filesystem is ~98% full with both node images staged.
- `RemoteActuatorBus::configureSensors` copies only a clamp's channel, so CT tuning built on the primary may never reach the wire (predates this branch).
- `GET /api/info` returns the API key unauthenticated.
- **Direction:** the numbers above say a C5 brain cannot be the answer for a large shop, and an S3 only buys headroom. The next work is a hosted brain (Raspberry Pi Zero 2 W) that reuses `shared/device-model`; a Node.js prototype is being run against these same nodes first. Nothing in this PR is wasted by that: nodes that dial their brain are what makes it work.
